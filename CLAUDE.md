# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

bazelex (binary `bazelex`) dumps the static target graph from `bazel query` into a SQLite database so it can be explored with SQL. `README.md` has usage, example queries and the schema rationale.

## Commands

Bazel is the build system (version in `.bazelversion`, use Bazelisk). The Go toolchain is managed by Bazel, so no local Go install is needed.

```sh
bazel test //...                                  # all tests
bazel test //internal/graphdb:graphdb_test --test_filter=TestLoad   # one test
bazel run //cmd/bazelex -- -db /tmp/g.sqlite      # run against this workspace
bazel run //:gazelle                              # after adding/removing Go files or imports
bazel run @io_bazel_rules_go//go -- mod tidy      # after changing Go dependencies
bazel run @io_bazel_rules_go//go -- fmt ./...     # gofmt
```

`BUILD.bazel` files are generated by gazelle. `go.mod` is the source of truth for Go dependencies: `MODULE.bazel` reads it through `go_deps.from_file`, and `mod tidy` also updates the `use_repo` list there.

Run the tool from inside a workspace. Under `bazel run`, `main` changes into `BUILD_WORKING_DIRECTORY` first, because Bazel refuses to be invoked from the runfiles tree. Keep that if you touch `run` in `cmd/bazelex/main.go`.

## Architecture

- `cmd/bazelex/`: flags, runs `bazel query --output=streamed_proto --keep_going` (default pattern `//...:all-targets`, because plain `//...` returns rules only) or reads that stream from stdin, then calls `graphdb.Load`.
- `internal/graphdb/`: `Schema` (the DDL, with column semantics documented inline) and `Load`, which reads length-delimited `Target` messages and writes `target` and `edge` rows in one transaction. After all inserts, one `UPDATE` resolves `edge.to_id`. It stays NULL for labels not in the loaded graph, such as external repos.
- `internal/buildproto/`: Bazel's `build.proto` and its checked-in generated Go bindings, vendored from bazel-contrib/buildtools. They are compiled as plain Go, so the root `BUILD.bazel` sets `# gazelle:proto disable`. Do not hand-edit `build.gen.pb.go`.

Edge extraction (`ruleEdges` and `labelsOf` in `load.go`) is the part that takes care:

- Edges come from every label-typed attribute kind, including each branch of `select()`. Select keys are recorded with `attr = '<select_condition>'`.
- `rule_input` entries that no attribute accounts for become `attr = '<implicit>'` edges.
- Generated files get a `<generating_rule>` edge to their rule.
- Duplicates within a rule are collapsed.
- Non-label attributes such as `tags` are not stored.
- Only `query` is supported, not `cquery`.
